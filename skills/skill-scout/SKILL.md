# 技能侦察

一句话：**先在自家技能库里找，再决定是补、是新建、还是装别人的。**

## 三种结论，先分流再做

| 判定 | 分数 | 动作 |
|---|---|---|
| 覆盖 | ≥ 0.40 | 直接用现成技能，不新建。缺的细节看它的 references |
| 部分覆盖 | 0.18–0.40 | **给现有技能补脚本或 references**，不另起一个 skill |
| 无关 | < 0.18 | 才考虑新建，或评估外部候选 |

分数只用于分流，不替代判断：0.40 上下几分的差距要自己看一眼说明再定。

## 工作流

### ① 建索引（一次就好，改了技能再重建）

```bash
python3 scripts/skill_index.py                 # 概览：几个技能、哪些说明还空着
python3 scripts/skill_index.py --md            # 全表：技能 / 中文名 / 脚本数 / 依赖
python3 scripts/skill_index.py --out /tmp/idx.json
```

默认扫两个根：`workspace/.user_skills`（自建，scope=user）与 `workspace/.skills`（平台内置，scope=platform）。依赖列已自动探测 `lark-cli / curl / subprocess / requests / playwright / openai / pandas` 等，用来判断"这东西在我们环境跑不跑得起来"。

### ② 匹配需求

```bash
python3 scripts/skill_match.py "周三要出联赛总结报告"
python3 scripts/skill_match.py "把云盘一个文件夹批量转 markdown" --top 5
```

输出：分数、判定、命中的中文词、脚本数与依赖。最后一行直接给结论（直接用它／补现有／新建）。

- 中文按二元组、英文按词打分，需求侧归一，所以短需求比长描述更容易拿高分；长句会被稀释，属正常，看排序即可。
- 平台技能大多没有中文名，此时括号里显示说明前 12 字，认人用 `name`。

### ③ 评估外部候选（重点：值不值得装）

```bash
python3 scripts/skill_match.py --candidate ./下载来的skill/SKILL.md
```

输出四行：候选名称、与本机技能的最大重叠（前 3）、结论（高重复／有互补／新增能力）、依赖线索。判读规则：

- **重叠 ≥ 0.5**：高重复。除非它解决的是现有技能明确做错的事，否则不装——两套并存以后必然口径打架。
- **重叠 0.25–0.5**：有互补。先看它的 references/scripts 是否能被现有技能引用，而不是整个装进来。
- **重叠 < 0.25**：新增能力。再查依赖：要 `openai`/付费 API/未登录账号的，先确认本环境能不能跑通，否则装进来也是摆设。

### ④ 外部候选从哪来

- GitHub：用 GitHub 插件的仓库搜索，关键词带 `skill`、`SKILL.md`、领域词，看 star 与最近提交。
- 定时任务「GitHub竞彩Skill日报」已在跑每天一轮外部扫描，直接看它的产出，不必重复搜。
- 拿到候选先落地成本地文件，再跑 `--candidate`，不要凭 star 数直接装。

## 结论怎么写

三行以内，不要写成长文：

```
判定：覆盖 / 部分覆盖 / 没覆盖
依据：命中技能 + 分数 + 命中词（部分覆盖要写清缺哪块）
动作：用它 / 补 scripts/xxx.py / 新建（理由）/ 不装（重复或依赖跑不通）
```

## 边界（别越权）

- **没有市场检索接口**：本环境没有 `find_plugin` / `suggest_plugin`，也没有可查询的技能商店，所以只能查"已装清单 + 你提供的外部候选"，不能像 `find-skills` 那样在线搜库。
- **不做一键安装**：安装位置和启用仍需用户确认，本技能只给判断和安装建议。
- **不改别人的技能**：平台技能（`workspace/.skills`）只读；要改就复制到 `.user_skills` 另存。
- **不把索引当缓存真理**：新增/改名技能后重跑 `skill_index.py`，否则匹配结果过时。

## 实测样例（可当回归用例）

| 需求 | 命中最高的技能 | 分数 |
|---|---|---|
| 周三要出联赛总结报告 | `jczq-league-report`（联赛总结报告） | 0.67 覆盖 |
| 把云盘一个文件夹批量转成 markdown | `drive-doc-to-md` | 0.82 覆盖 |
| 赛前帮我拉一下 xG 数据 | `football-data-xg` | 0.83 覆盖 |
| 明天要发周报和日程摘要 | `lark-workflow-standup-report` | 0.22 部分覆盖 |
| 帮我做个海报 | `doubao-creative-design` | 0.25 部分覆盖 |

跑出来与上表差得远，说明技能库变了（新装/改名/改了 description），先重建索引再判。

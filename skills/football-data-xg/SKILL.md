# 实测 xG 提取

## 为什么用这个源

足球数据里最容易出错的一环是 xG。知识库原来的 `L1_003竞彩xG与xGa` 多是网络/AI 推算值，每次使用都要按「xG 核验协议」用 7 表格反推 `g = 场均射门 ÷ 射门进球效率` 做二次核验，命中率还不高（首版 12 场里只有 2–3 场能升 ✅）。

football-data.co.uk 的 `HxG/AxG` 是**实测值**（Opta 系数据商口径），按同一份协议属 **S/A 级实测源，免检**。所以这条流程的价值不是"多一个数据源"，而是**把 xG 从"需要验证的推测"变成"可以直接用的实测"**。

同源还免费附带：全场/半场比分、射门/射正、角球、犯规、红黄牌、十余家欧赔、亚盘让球线。一次抓取能同时喂多个环节。

## 三步流程

### 第 1 步：跑脚本取数

```bash
# 单联赛
python3 scripts/xg_fetch.py --league 意甲 --season 2627 --outdir ./xg_out

# 五大联赛一次跑完
python3 scripts/xg_fetch.py --all --season 2627 --outdir ./xg_out

# 顺带与知识库/8BO 的比分交叉校验（强烈建议，用来证明两源一致）
python3 scripts/xg_fetch.py --league 英超 --season 2627 --outdir ./xg_out \
    --compare /sandbox/workspace/ts/data/英超/matches.csv
```

- `--season` 用两位年份拼接：`2627` = 2026-27，`2526` = 2025-26（可回溯历史赛季做基线）
- `--league` 支持中文名或代码：英超/西甲/德甲/意甲/法甲，或 E0/SP1/D1/I1/F1（完整码表见 `references/leagues.md`）
- `--window` 滚动窗口，默认 6 场
- `--compare` 传 8BO 的 `matches.csv`，脚本会做队名归一后逐场比比分

站点偶发超时，脚本内置 3 次重试；仍失败就换时间重跑，不要改抓取方式（urllib 直连会被拦，必须走 curl）。

### 第 2 步：读产出

`--outdir` 下会有三个文件 + 可能的汇总：

| 文件 | 内容 | 用在哪 |
|---|---|---|
| `{联赛}_matches_xg.csv` | 逐场：日期/主客/比分/xG/xGa/结果/亚盘 | 查单场、做自定义窗口 |
| `{联赛}_teams_xg.csv` | 队级：场均 xG/xGa/xG差、进球−xG、失球−xGa、主客拆分、近 N 场滚动 | 写报告、做先验 |
| `{联赛}_xg_report.md` | 上面两张表的 Markdown 版 + 读法 | 直接贴进报告 |
| `xg_all_summary.md` | 五联赛 xG差 Top5（`--all` 时） | 横向快速扫 |

### 第 3 步：接入使用

按用途选维度，不要一股脑全塞进结论：

- **判断球队真实强弱** → 用 `xG差`（进攻创造 − 防守让出），它比净胜球稳定，剔除了射术/门将的噪声
- **判断"数据虚不虚"** → 用 `进球减xG`：> +0.5 是射术/运气超额，短期易回落；< −0.5 是机会有但转化失速，属可修复
- **判断防守是否会回归** → 用 `失球减xGa`：> +0.5 说明门将/防线被过量进球，未来大概率改善；< −0.5 是门将超额扑救，不可持续
- **判断趋势拐点** → 用「近 N 场 vs 全季」偏离：只有偏离 ±0.25 以上才算趋势成立
- **主客差异** → 用主客拆分，不要用全季均值（本季五大联赛主客盘路反转普遍，全季均值会掩盖）

## 数据新鲜度与时区（每次调用都要看）

xG 是**赛后产物**——没有比赛就没有本场 xG。所以这份数据永远是「截至某个已完成轮次」的历史值，用途是先验层与画像层，**不是本场预测**。

两个容易踩的坑：

1. **日期是英国当地时间**，与北京时间差约 8 小时。英国晚间比赛（如 16:30 / 20:00 开球）= 北京次日凌晨。看到"数据截至 11-08"不要以为漏了 11-09 凌晨那场——它就在里面，日期记的是英国时间。脚本已在输出里标注这一点。
2. **入库是 T+0～T+1**：当天比赛当天或次日入库，速度与 8BO 相当。若发现最近一轮整轮缺失，才可能是尚未入库。

脚本每次运行会自动打印 `数据截至 X（英国时间，北京+8h）｜距今 N 天`，并在 N ≥ 2 时给核对提示：

- **N = 0～1**：正常，直接用
- **N ≥ 2**：先核对最近一轮是否已全部战罢。若已战罢但数据里没有 → 尚未入库，**退回上一轮滚动值**（用 `近N场_场均xG` 的上一个版本），并在报告里注明「xG 数据截至 R{X}」，**不要用估算或其他源填补**

## 口径边界（写结论前必须知道）

1. **不含点球**：该源 xG 为开放进攻口径，与含点球的商业口径不可直接比。
2. **跨数据商不可比**：Opta / StatsBomb / Wyscout 的 xG 绝对值有系统性差异，同一场能差 0.2–0.3。引用时必须写明"football-data（Opta 系）"。
3. **无未来赛程、大小球只有 2.5 固定盘**：需要赛程或实际盘口档位时，必须并用 8BO。
4. **盘口口径与 8BO 有 0.25 档差**：实测英超 100 场，让球线 41 场不同、赢盘判定 4 场不同。**跨源比较赢盘率必须锁定同一源**，不可混算。
5. **队名是英文**：脚本内置五大联赛中文映射，未收录的队会原样保留英文，不要自行猜译名。
6. **只能用于赛前先验，不能当本场预测**：正确姿势是「取该队近 6 场 xG / xGa（截至上一轮）→ 与对手 xGa / xG 对照 → 得预期进球区间 → 与盘口交叉」。赛前单场分析里它属先验层，不进临场层。

## 两个典型用法

**例 1：赛前分析补第 3 维（攻防质量）**
> "帮我拉一下意甲 xG" → 跑 `--league 意甲` → 读 `意甲_xg_report.md` 第二章找出主客裂口大的队，第三章找出近期上行/下行的队 → 把 `xG差` 与 `进球减xG` 写进 Step1 的攻防维度，替代原来的 AI 推算值，并在报告注明"实测源、免检"。

**例 2：验证一个"战绩虚高"的怀疑**
> 某队积分靠前但用户怀疑其内容质量 → 看 `xG差` 是否显著低于净胜球、`进球减xG` 是否 > +0.5。若两者同时成立，就是"结果好于内容"，可作为下修依据；若 `xG差` 反而更高，说明是防守端在托底，结论要反过来写。

## 与现有体系的接口

- **替代** `L1_003竞彩xG与xGa` 的 AI 推算值（同类指标但免检）
- **供** 「赛前分析」Step1 的攻防质量维度、「球队数据服务」第三章的攻防结构、联赛阶段总结的攻防异常指标
- 若需长期沉淀，把 `{联赛}_xg_report.md` 归档到知识库 `L1_003竞彩xG与xGa`（folder_7514224813156281），命名 `实测xG_{联赛}_第N轮_{YYYYMMDD}.md`

## 第二源：football-charts.com（2026-11-23 接入，交叉校验用）

footballcharts-mcp（`ddevetak/footballcharts-mcp`）背后的 REST API 已接成本地脚本 `scripts/fc_fetch.py`，不依赖 MCP 客户端，直接 urllib 直连。

**为什么接它**：football-data.co.uk 只有五大联赛有 xG，欧战没有、且要按赛季整包抓；这个源一次调用就能拿队级 xG，并且**天然带下一场赛程（含模型概率）**，可用来补情报包的赛程与基线概率。

**额度**（先看清再跑）：

- 无 key：**25 次/天/IP**（20 次/分钟）——够跑五大+荷甲+葡超 7 个联赛各 1 次队级查询（7 次）
- 免费 key：200 次/天（邮箱确认前 100），60 次/分钟 → `export FC_API_KEY=fc_xxx`
- 注册 key：`curl -X POST https://api.football-charts.com/api/v1/keys/register/ -H 'Content-Type: application/json' -d '{"email":"..."}'`，key 只显示一次
- 脚本自带 6 小时本地缓存（`~/.cache/fc_api`），重复查看不烧额度；`--no-cache` 强制刷新

**常用命令**：

```bash
python3 scripts/fc_fetch.py leagues                       # 98 联赛 + 可查赛季
python3 scripts/fc_fetch.py team --league premier --team arsenal --outdir ./fc_out
python3 scripts/fc_fetch.py table --league premier        # 含 xPTS、luck_category
python3 scripts/fc_fetch.py fixtures --league premier     # 未来赛程 + 模型概率
python3 scripts/fc_fetch.py acheck                        # 逐联赛抽 1 队验 xG 覆盖（2 次/联赛）
```

**实测口径（2026-11-23 跑通，A 级口径 7 联赛）**：

| 项 | 结果 |
|---|---|
| 联赛覆盖 | 五大 + 荷甲（holland1）+ 葡超（portugal1）✅；**欧冠/欧罗巴 ❌ 无覆盖** |
| 赛季 | 只有当季 + 上一季 → 不能做多年回测 |
| 队级 xG/xGa | ✅ 有；A 级 7 联赛 **7/7 全量覆盖**（2026-11-23 `acheck` 验收，每队 with_stats = 已赛轮次，无缺场） |
| **逐场技术统计** | ❌ results 接口无 stats 字段（openapi 里的示例是"有"，实际 keyless 返回没有）→ 逐场回填仍走 football-data.co.uk |
| 赔率 | ❌ 全部无（欧赔/亚盘/大小球都没有；历史赔率库是付费数据集） |

**口径交叉校验（同日对比，很有用）**：

- Arsenal：本源 1.61 / 0.86（11 场） vs football-data 1.61 / 0.76（10 场）→ 进攻端**完全一致**，防守端差 0.10（样本差 1 场可解释）
- Barcelona：本源 3.31 / 1.12 vs football-data 3.24 / 1.11 → 差 2% / 1%

结论：两源底层大概率同源（Opta 系），**本源可当第二源做交叉校验与欧战缺口的补充观察**；但不得与 football-data 混算同一个"进球减xG"序列，引用时写清源名。

**边界**：只有 team / match 粒度，无球员 xG、无射门坐标；数据 © football-charts.com，个人与研究用途免费但要署名 `Data by football-charts.com`，禁止转售。

### 双源对照与赛果对账（2026-11-23 起的日常动作）

```bash
# 双源 xG 对照：7 联赛各取前 N 队，与 football-data 逐队比（默认 top6 → 7*(1+6)=49 次额度）
python3 scripts/fc_fetch.py dual --top 6 --outdir ./数据分析/footballcharts

# 赛果对账：FC 赛果（含半场/首球分钟）与 football-data 原始 CSV 逐场比
python3 scripts/fc_fetch.py resultcheck --outdir ./数据分析/footballcharts
```

**判读规则（dual）**：ΔxG 与 ΔxGa 同时 > 0.10 → `⚠双差`，回 football-data 复核；只有 ΔxGa > 0.10 → `⚠`，先看样本差（FC 常比 football-data 多一轮）；其余 `ok`。

**判读规则（resultcheck）**：全场/半场不一致应为 0。出现不一致 → 该场两边必有一错，回官方赛果核对。`仅FC有` 多为 football-data 尚未入库的新轮次（T+1 延迟），不是缺数据。

**2026-11-23 首跑基线**：dual 42 队 → 41 队可选、除 Sporting CP 外全部匹配；resultcheck 可比 637 场，**全场不一致 0 / 半场不一致 0**，首球分钟覆盖 602 场（94.5%）。这条已证明两源比分可信，可当 Step3 复盘的第二校验源。

### 中文队名 → slug 映射（2026-11-23 补，链路上线前置）

竞彩清单里的队名是中文（「特温特」「威廉二世」「尤文图斯」），接口只认 slug，所以 `references/team_names_cn.csv` 是必需件，格式 `cn,league,slug`，现 191 行（五大 ~120 + 荷甲 22 + 葡超 22 + 常见简称）。

- `team` 子命令会自动查表：`[映射] 巴萨 → barcelona`；查不到则退化到「按英文名在本联赛队表里归一匹配」
- 两者都失败 → 明确报 `[404] <联赛> 下找不到队 <名>`，**不要瞎猜 slug**
- 新增球队（升降级）时直接在 CSV 追加一行即可，不用改代码

**已知覆盖缺口**：荷甲/葡超之外的次级与低级别联赛无中文映射（本就不在 A 级口径内）。当日出现新队时按缺口记「xG不可得」，下次补表。

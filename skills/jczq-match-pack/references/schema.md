## 键格式（实测）

- 统一键主表：`261116-周一006`（YYMMDD-周XNNN），`is` 精确命中
- 画像键：`拜仁慕尼黑|主场`、`斯图加特|客场`
- 交锋键：`拜仁慕尼黑|斯图加特`
- 比赛键（赛果表）：`2627-德甲-2026-08-28-拜仁慕尼黑vs斯图加特`

## 特征桶档位（实测，不是猜的）

- 身价比：`≤0.7` / `0.7-1.0` / `1.0-1.4` / `1.4-2.5` / `≥2.5`
- 综合评分差：`≤-15` / `-15~-5` / `±5` / `5~15` / `≥15`
- 控球率差：`≤-10` / `-10~-3` / `±3` / `3~10` / `≥10`

「赛前特征响应」表只有 全样本 / 赛事等级 两个维度，**没有联赛维度**；要按联赛取分布只能用「玩法分布」表（该表有联赛维度）。

「玩法分布」的条件档是赔率区间（`1.00-1.30`/`1.30-1.50`/`1.80-2.20`/`2.20+`/`无初赔`），让球是 `+1`/`-1`/`≤-2`，比分是 `5.0-7.0`/`7.0-10.0`。

## 数据坑（每条都实测过）

1. **001 表「比赛ID」与主表「比赛ID」不同源**：001 里是 `M0262` 这类短码，主表是 `166651` 这类数字，按比赛ID直接过滤永远查不到。正确路径：主表取 link 字段 `赛前静态数据（001）` 的 record id → `+record-get --record-id` 读 001。
2. **`+record-get` 返回的字段顺序以返回体自带的 `fields` 数组为准**，不是 `+field-list` 的顺序；按 field-list 映射会串列（曾把身价读成评分）。
3. **两种 filter 语法不通用**：
   - `+record-list`：`{"logic":"and","conditions":[["字段","==","值"]]}`
   - `+data-query`：`{"type":1,"conjunction":"and","conditions":[{"field_name","operator","value"}]}`
4. **文本字段不支持 `intersects`**（报 800004006），只允许 is/isNot/contains/doesNotContain/isEmpty/isNotEmpty/isGreater/isGreaterEqual/isLess/isLessEqual。
5. **`+data-query` 的 sort 不要用 alias**，用真实字段名；用 alias 排序会静默返回空。
6. **`+data-query` 里 dimensions 与 measures 用同一字段名（如 统一键/画像键）是允许的**，写 count_all 即可。
7. **一个条件里给文本字段传多个值（is + 数组多值）不可靠**，拆成多次单值查询再合并最稳（脚本里画像层就是这么做的）。
8. **主表队名可能是简称**（`尤文`），赛果表可能是全称（`尤文图斯`）；近10场查询要用原名回退。
9. **001 的 xG 字段经常为空**，xG 实体值在「xG实测画像」表；001 为空不算缺口。
10. **A级联赛统计表只覆盖俱乐部联赛**（21 条，总场次口径 ≠ 赛果表全量），引用时必须带「口径」和「可回测场次」。

## 国家队分支

联赛名含 `欧国联`/`友谊`/`预赛`/`欧洲杯`/`世界杯`/`亚洲杯`/`美洲杯`/`非洲杯`/`国家联赛`/`亚运`/`奥运`/`联合会杯` 即判定为国家队赛事：

- 球队画像、xG画像、交锋画像、A级联赛统计 **统一标「本层不适用」**，不计缺口（这些是俱乐部口径）
- 历史战绩改从国家队赛果库取近 10 场，**不分主客**（国家队样本少）
- 队名需中英映射，脚本内置约 90 个常用国家队；未收录的保持原名并如实标注，不猜译名

# 库内六层 + 外部情报的汇合契约

两个 Skill 各自独立，谁也不依赖谁：

- `jczq-match-pack`：从 Base1 取已完赛历史与基线（L1–L6）；赛前场次由 L1D 文档层（`--doc`）补位。
- `football-match-data-collector`：从外网抓伤停/阵容/盘口/环境，输出 facts v1 包 + 单场 MD。

汇合发生在本脚本的一个参数上，不新增第三个 Skill。

## 一、调用方式

```bash
python3 scripts/match_pack.py 清单.json --date 2026-11-17 --out 011/情报包.md \
  --external <facts.json> <单场情报包.md> ...
```

`--external` 可混传、可多个、可省略。省略时退化为纯库内包，格式不变。

## 二、输入契约

| 输入 | 必需内容 | 编号来源 |
|---|---|---|
| facts JSON | 根对象 `"schema":"v1"`、`matches[]` 每场含 `match_id`/`collect_as_of`/`kickoff_at`/`completeness`/`missing`/`facts` | `match_id` 前 6 字，如「周二006 丹麦vs挪威」→ `周二006` |
| 外部 MD | 头部行 `竞彩编号：周二006` + 第 5.1/9/10/11 段 | 头部「竞彩编号」字段 |

编号取不到时该文件跳过并打印，不猜。

## 二点五、L1D 与 L7 的分界

- **L1D**：001 文件夹的 7 表格 + 历史战绩，经 `parse_001.py` 归一后由 `--doc` 传入。它是**赛前主数据**（实力、攻防、同主客近10、交锋、赛程、场地天气、初赔）。
- **L7**：只装 001 文档里没有的赛前动态（伤停、预计首发、盘口初值/即时、环境确认）。
- 两者都属赛前，但 L1D 是结构化文档事实，L7 是外部采集；同一字段冲突时并列标 `[源冲突]`，不互相覆盖。

## 三、L7 装什么

| 内容 | 来源 | 说明 |
|---|---|---|
| 外部伤停与人员变动 | facts JSON | 只列 `player_unavailable / player_return / lineup_confirmed / lineup_expected` 四类 |
| 5.1 阵容 | 外部 MD | 含阵型来源、缺阵位置、主帅表态 |
| 9 盘口 | 外部 MD | 只保留数值表 + 三方对照；描述性 bullet 默认丢弃（`--l7-full` 可保留）。**合包前必须先过时点校验，见第五节** |
| 10 环境 | 外部 MD | 场地、天气、裁判、观众 |
| 11 情报缺口 | 外部 MD | `completeness` + `missing` |

`slim`（默认开）额外做一件事：外部 MD 第 5 段（伤停）与 facts 表重复，不再引用，只留 facts 表。

## 四、赛前未入库的处理（关键）

Base1 主表只存已完赛数据，赛前场次（尤其国家队、临时新增）查不到属正常设计，不是采集失败。旧版会整场跳过。接入 `--external` 后改为：

- 该场仍入包，标题标「（赛前未入库·设计如此）」
- L1–L6 明写「赛前未入库（Base1 主表仅存已完赛数据，设计如此），本节不适用，不计缺口」，**不伪造历史数据、不把设计如此说成数据缺口**
- L7 正常渲染

既没有 `--doc` 也没有 `--external` 时才跳过；只有 `--doc` 也能让赛前场次入包。

## 五、两源冲突

同名字段两边不一致时（典型：库内 006 初赔 vs 当场抓的竞彩 SP；库内让球数 vs 外部让球），**两值并列标 `[源冲突]`，不自动择一**，由分析端判断。L7 末尾固定输出这一提示。

## 五点五、盘口时点闸（合包前置，硬性）

外部盘口有两个已实测的失真源，必须在合包前拦掉，否则 L7 会带着错值进入 Step1：

1. **懂球帝页面无时间戳**，「即时」列可能残留早段值（261117 周二006 采集于 19:25，页面给的却是 11:30 的 0.84/平手/1.00 与 2.28/3.83/2.73，008 的 19:00 实为 0.94/0.90 与 2.52/3.93/2.45）。
2. **大小球三列列序会变**，按「盘口｜大｜小」硬解会把大/小球水位互换（同场把 3.5 大1.04/小0.76 读成 3 大0.76/小1.04）。

合包时按下面的闸执行：

```bash
python3 <collector>/scripts/check_odds_vs_008.py --odds odds_006.json --report 008_<日期>_终报.md
python3 <collector>/scripts/check_odds_vs_008.py --columns "0.76 3 1.04"   # 无 008 时的列序自校
```

| 校验结果 | L7 怎么渲染 |
|---|---|
| PASS | 正常；三方对照后加一行「已与 008 · {参照时点} 交叉校验」 |
| FAIL + 外部已标 `[时点存疑]` | 保留标记与参照时点；「升降盘 / 欧亚背离」整段降级为「未校验，不判定」 |
| FAIL + 外部未标 | 盘口段写「盘口时点存疑，未校验，不予采信」，并计入 L7 缺口 |
| 008 不存在 | 盘口只作「初盘/参考值」，禁写即时盘与背离 |

参照时点取「不晚于 `captured_at` 的最近一个 008 时点」，不得用后一个时点反推。

## 六、缺口语义不换算

| 口径 | 含义 | 能不能换算 |
|---|---|---|
| L6 质量门 | 库内各层命中情况（001/006 关联、画像、交锋、基线、特征桶） | 不能 |
| L7 `completeness` | 外部必采 12 项完成度 | 不能 |

两套并列呈现，不合成一个总分。

## 七、页数预算

| 模式 | 单场约 | 单包上限 |
|---|---|---|
| 纯库内 | 3 页 | 8 场（约 18–20 页） |
| 含 L7（slim） | 3.5–3.8 页 | **建议 ≤5 场**（实测 2 场 7.4 页） |
| 含 L1D+L7 | 约 6 页 | **建议 ≤3 场**（实测 2 场 12.0 页） |

脚本超 `--max-pages`（默认 20）即退出码 1 并要求拆包。含 L7 按 5 场一批，含 L1D+L7 按 3 场一批规划。

## 八、交付

- 主件落 `011_红利模型成果`，副本 `016_单场纯分析`
- 文件名 `YYMMDD_赛前情报包_周X001-00N.md`
- 只在包尾保留一处「缺口汇总」，各场明细见 L6 与 L7 缺口段

## 九、失败处理

| 情况 | 行为 |
|---|---|
| `--external` 文件不存在 | 打印跳过，L7 标「未提供外部数据」，库内照常 |
| facts 缺 schema | 打印 `未标`，不阻断（校验器那边会告警） |
| 外部 MD 缺某段 | 该段不渲染，其余照常 |
| `--doc` 未覆盖该场 | L1D 标「001 文档未覆盖本场（真缺口）」，其余照常 |
| 库内、文档、外部都缺 | 场次跳过并列出原因 |

# 竞彩足球赛前数据采集

## 概述

按标准化流程采集一场比赛的全部原始数据，输出结构化的原始数据包，供后续赛前分析使用。核心原则：**只搬运和核对，不做主观判断**。

## 触发口令（用户口头说法 → 本 Skill 动作）

用户不必报队名、联赛、场地、文件路径；编号 + 日期足够定位。缺项按下面默认解析。

| 口令 | 解析出的动作 |
|---|---|
| `采 <日期> <编号…> [截点HH:MM]` | 本 Skill 主入口：逐场采集 11 个模块 → 出单场情报包 MD + 同期 facts JSON + `odds_<编号>.json` → 跑 `validate_intel.py` 与 `check_odds_vs_008.py` |
| `情报 <日期> <编号…> [截点HH:MM]` | 全链：本 Skill 采集校验后，交 `jczq-match-pack` 并入库内六层 + L7 合成一份包 |
| `校验` | 对当前 facts JSON 跑 `scripts/validate_intel.py`，再对 `odds_<编号>.json` 跑 `scripts/check_odds_vs_008.py`；任一 FAIL 不得交付 |
| `回归` | 跑 `tests/run_regression.py` 与 `tests/run_odds_regression.py`，任一退出码非 0 说明能力退化，先修再上批次 |
| `重采 <编号>` | 只补采指定场次，不动同批其他已交付包 |

解析规则：

- 编号只写后三位（`006`），星期由 `<日期>` 推出，不必写「周二」。
- 截点省略时按「现在」取，但**必须早于开赛**；一旦定下，整份包只用这一个截点，后续发布的首发/伤退进「越界拒收」。
- 多场同批采，仍**每场单独出一份包**；合成一份汇总包是 `jczq-match-pack` 的职责，本 Skill 不做。

## 工作流程

### Step 1：比赛初筛

确认比赛是否适合采集，并定级：

- A 级：五大联赛、欧冠、欧罗巴等 A 类赛事池，全流程深挖
- B 级：主流次级联赛、日韩联赛、国家队正式赛事，结构化源优先
- C 级：低级别联赛、友谊赛、青年赛、预备队比赛。默认只采官方公告与竞彩盘口，不深挖；用户明确要求时才升级采集深度
- 开赛时间过早且数据来源稀缺的场次，直接标 `completeness` 偏低并说明原因，不得硬凑
- 记录基础信息：联赛、轮次、开赛时间、主队、客队、场地、竞彩编号

### Step 2：逐场数据采集

按以下 10 个模块 + 阵容、情报缺口逐项采集。详细字段清单见 [references/collection-checklist.md](references/collection-checklist.md)，推荐数据源见 [references/data-sources.md](references/data-sources.md)，facts 字段与时间闸见 [references/intel-facts.md](references/intel-facts.md)。

| 序号 | 模块 | 核心内容 | 优先级 | A 级 | B 级 | C 级 |
|------|------|---------|--------|------|------|------|
| 1 | 基础信息 | 联赛、轮次、时间、场地 | 高 | 官方 | 官方 | 官方 |
| 2 | 近期状态 | 双方近5/10场战绩、进失球、xG/xGA | 高 | 多源 | 单一结构化源 | 竞彩+官方 |
| 3 | 主客场 | 双方主/客场近5场表现 | 高 | 多源 | 单一来源 | 竞彩+官方 |
| 4 | 交锋历史 | 近3-5次交锋结果、进球数 | 中 | 多源交叉 | 单一来源 | 单一来源 |
| 5 | 伤停 | 主力伤停、缺阵原因、预计复出、缺阵分钟 | 高 | 双源深挖 | 结构化源 | 仅官方公告 |
| 5.1 | 阵容 | 已公布首发、预计首发、门将、各位置缺人情况、阵型及来源 | 高 | 官网+跟队+懂球帝 | 懂球帝/官方 | 仅官方 |
| 6 | 赛程 | 近14天场次、rest_days、下一场对手及重要性 | 高 | 全量 | 全量 | 全量 |
| 7 | 战意 | 排名、积分、场次、净胜球、剩余轮次 | 中 | 多源 | 单一来源 | 竞彩+官方 |
| 8 | 战术 | 控球率、射门转化率、抢断/拦截/解围、定位球、阵型 | 中 | 多源 | 结构化源 | 可缺 |
| 9 | 盘口 | 欧赔、亚盘、大小球的初始值与即时值（多公司）+ 三方对照背离段 | 高 | 全量 | 全量 | 全量 |
| 10 | 环境 | 天气、场地、裁判（姓名、场均出牌）、上一场时间 | 中 | 多源 | 结构化源 | 可缺 |
| 11 | 情报缺口 | `completeness` + `missing[]`（含尝试过的来源） | 收口必填 | 必填 | 必填 | 必填 |

采集深度分级（按赛事层级，不是按联赛名气）：

- **A 级**：五大联赛、欧冠、欧罗巴等 A 类赛事池。全模块多源深挖，伤停与阵容必须双源互证。
- **B 级**：主流次级联赛、日韩联赛、国家队正式赛事。结构化源优先（懂球帝公开接口、API-Football），不够再补一次检索。
- **C 级**：低级别杯赛、青年队/预备队、友谊赛。只采官方公告与竞彩盘口，`facts` 允许为空，但必须在 `missing` 写明"未深挖（C 级）"。

采集方式：A 级用 `general_search` 检索并 `web.fetch` 精读；B/C 级优先调结构化接口，失败再回退检索。伤停与阵容信息必须交叉验证。

盘口单独走固定入口，不再逐场检索：用 `web_fetch` 打开 `https://m.dongqiudi.com/matchDetail/{matchId}/lotteryOddsNew?cmp_type=soccer`（`matchId` 与阵容页同号），一次拿到亚盘/欧指/大小球的初始与即时值。取数口径、换算、变盘与背离标记、降级链见 [references/odds-collection.md](references/odds-collection.md)。

### Step 3：数据校验

采集前先定 `collect_as_of`（本次采集截点，必须早于开赛）。所有字段都要过下面五道闸：

1. **时间闸（硬性）**：每条数据必须满足 `observed_at <= collect_as_of < kickoff_at`。页面无可确认发布时间时不许猜，记入 `missing` 并注明"发布时间不可确认"。截点后发布的首发、伤退、赛果一律拒收，在输出末尾单列"越界拒收"区备查。
2. **来源分级**：L1 官方公告/官方首发/主帅发布会可单独确认；L2 通讯社与跟队记者需两条一致；L3 结构化伤病源、Transfermarkt 需与 L1/L2 互证；L4 聚合站与社媒只作线索，不入 facts。
3. **伤停与阵容**：按 facts 协议落字段（见 `references/intel-facts.md`），至少包含 `status / source_url / observed_at / credibility / event_fingerprint`。同一事件只留一条，按 `event_fingerprint` 去重。
4. **盘口**：按 `references/odds-collection.md` 走固定入口，初始与即时必须成对；至少对比 2 家公司，记录变盘方向与「竞彩-欧赔背离」等标记，只描述不判断；禁止去水、算返还率或写「诱盘」。
   - **列序先自校**：大小球行三列按数值特征判序（盘口 2.5–5.0、水位 0.60–1.20），不得按位置硬解，否则大/小水位互换（`--columns` 可自校）。
   - **时点必交叉校验**：页面无时间戳，「即时」列可能残留早段值。抓完必须与当日 `008` 同一场「不晚于采集时点的最近时点」比对，欧指 >3%、亚盘让球 ≥0.25 格或水位 ≥0.05、大小球盘口不等 → 判 `[STALE_*]`，该段不得交付、不得用于背离判定；大小球两水位与 008 正好互换 → 判 `[SWAP_TOTAL_WATER]` 并按 008 归位。
5. **缺失处理**：缺失写"未获取"并附尝试过的来源，禁止脑补，禁止用射门数、控球率冒充 xG 或 PPDA 等未提供指标。

校验脚本（必跑，两道闸全过才交付）：

```bash
python3 scripts/validate_intel.py <intel.json>                 # facts 五项断言
python3 scripts/check_odds_vs_008.py --odds odds_006.json --report <008 终报>.md   # 盘口时点/列序
```

任一 FAIL 即不得交付。008 尚未生成时，`check_odds_vs_008.py` 输出「无法交叉校验」警告，盘口只作参考值、背离段整段写「未校验，不判定背离」。

改动本 Skill 自身（字段、枚举、阈值、脚本）后，先跑两道回归：`python3 tests/run_regression.py`（facts 契约）与 `python3 tests/run_odds_regression.py`（盘口拦截，含 261117 的三份实跑样本），任一退出码非 0 说明能力退化，修好再上新批次。

### Step 4：输出原始数据包

每场比赛输出一份结构化数据包。**Markdown 是唯一主产物，CSV 只在回测合并时由 MD 派生**，不做双份维护。

- 主产物：`match_intel_YYYYMMDD_主队vs客队.md`（UTF-8、GFM 表格、数字不改写）
- 配套 facts JSON：根对象带 `"schema": "v1"`；这份 JSON 与上面的 MD 一起构成对外交付单元，可直接作为 `--external` 传给 `jczq-match-pack`，由它并入库内六层合成一份完整赛前情报包
- 配套盘口快照 `odds_<编号>.json`：`schema: "odds-v1"`，字段见 `references/odds-collection.md` §二点五；它是交叉校验与复盘的机读凭据，与 MD 同批交付
- 派生：需要回测入库时才生成 CSV，字段参考 [assets/match-data-template.csv](assets/match-data-template.csv)
- 回复中只给文件绝对路径 + 关键缺口，不粘贴整份表格

MD 头部固定八行：

```text
采集截点：YYYY-MM-DD HH:MM
竞彩编号：周四001
联赛 / 轮次：英超 第12轮
开赛时间：YYYY-MM-DD HH:MM
数据源：官网 / 跟队记者 / 懂球帝 / 竞彩官网
completeness：0.75
facts_schema：v1
facts：12 条（确认 8 / 待确认 4）
```

facts JSON 的根对象同样带 `"schema": "v1"`；交付前跑 `validate_intel.py`，schema 版本不受支持会直接 FAIL。

正文按 11 个模块排列，必须包含：

- 全部模块的采集结果（A 级全量，B/C 级缺失项显式留空）
- 每项数据的来源与 `observed_at`
- 确认状态（`[确认]` / `[待确认]` / `[未获取]` / `[不适用]` / `[越界]`）
- 第 9 模块盘口必须含「三方对照」固定段：竞彩 SP、欧指均值、亚盘共识的初始→即时数值与相对变动，并列出背离类型；无背离写「无背离」
- 第 9 模块的「即时」值必须标注**校验状态与参照时点**（如「即时 0.94/0.90（已与 008 · 19:00 交叉校验，通过）」或「`[时点存疑]` 页面给 11:30 值，按 008 · 19:00 校正」）；未标状态的盘口值视为未校验
- 大小球必须写全「盘口｜大｜小」三项，禁止只写盘口或只写一侧水位
- 第 11 模块情报缺口：`completeness`、`missing[]`（含尝试来源）、未深挖项
- 末尾"越界拒收"清单（有则列，无则写"无"）

## 注意事项

- 本 Skill 不输出概率、赔率分析、xG 调整或投注建议，那些属于后续分析环节
- `facts` 只写事实与依据，不写"对胜率影响"这类推断
- 不输出「防守强度」「裁判执法风格」「排名压力」「阵容完整度」等定性标签：这些由采集者主观判定，属分析层。只给可核验数值（抢断/拦截/解围次数、场均出牌、排名积分、缺阵位置）
- 数据采集不完整时明确告知缺失项，不强行凑数，不用射门数/控球率冒充 xG
- 同一联赛多场比赛可批量采集，但每场单独输出数据包
- C 级赛事允许 `facts` 为空，但 `missing` 必须写"未深挖（C 级）"
- 采集到的盘口数据为初盘/中盘，临场终盘需在临场刷新环节重新记录
- 盘口「即时」值不校时不写：「无时间戳 + 未与 008 交叉校验」的数值只能标 `[时点存疑]`，不得作为 L7 的即时盘、不得推出升降盘或欧亚背离
- 赛后统计（控球、射门、xG 等）不得当作赛前特征使用，即使在同一比赛页面上一并出现

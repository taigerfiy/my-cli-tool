# 数据采集字段清单

每场比赛按以下字段逐项采集，缺失填"未获取"。

## 1. 基础信息

| 字段 | 说明 | 示例 |
|------|------|------|
| 联赛 | 联赛全称 | 英格兰足球超级联赛 |
| 轮次 | 第几轮 | 第5轮 |
| 开赛时间 | 精确到分钟（当地时间） | 2026-09-14 22:00 |
| 主队 | 球队全称 | 曼彻斯特联 |
| 客队 | 球队全称 | 利物浦 |
| 场地 | 球场名称 | 老特拉福德球场 |

## 11. 情报缺口（收口必填）

| 字段 | 说明 |
|------|------|
| completeness | 已采必采字段数 / 必采字段总数，0–1（必采=模块1、2、3、5、5.1、6、9） |
| missing[] | 缺失项列表，每条必须写"缺什么 + 尝试过哪些来源" |
| 未深挖项 | C 级赛事固定写"未深挖（C 级）"，不得留空当已采 |
| 越界拒收[] | 因 `observed_at > collect_as_of` 被拒的条目，注明原来源与发布时间 |
| 接口降级 | 结构化接口失败时记录 `接口:错误`，主流程继续，但 completeness 相应下调 |

`completeness` 不得手填估计值；低于 0.6 时 `missing` 必须非空，否则视为造假。

## 采集状态标注规范

每项数据必须标注状态：
- `[确认]`：数据已采集且来源可靠
- `[待确认]`：仅单一来源或信息有矛盾
- `[未获取]`：尝试采集但未找到可靠数据，需在后附尝试来源
- `[不适用]`：该字段对本场比赛不适用（如杯赛阶段对联赛）
- `[越界]`：有值但发布时间晚于采集截点，已拒收，移入越界清单

每条带时间敏感性的数据（伤停、阵容、盘口、天气、裁判）必须附 `observed_at`。只有数值没有时点的条目，按 `[待确认]` 处理。

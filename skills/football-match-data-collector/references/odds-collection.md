# 盘口采集规范（模块 9）

## 一、固定入口

懂球帝比赛页的指数子页，按 `matchId` 直接取全市场盘口：

```text
https://m.dongqiudi.com/matchDetail/{matchId}/lotteryOddsNew?cmp_type=soccer
```

- `matchId` 从阵容页 URL 同一段取（`/matchDetail/{matchId}/lineup`），无需另搜。
- **必须用 `web_fetch`**：页面由 JS 渲染，`curl` 只能拿到壳，正文里没有盘口数字。
- 返回三段：亚盘（15 家）、欧指+凯利（17 家）、大小球（15–17 家），每段都是「初始 / 即时」。

实例：261117 周二006 = 54419587，周二007 = 54419588。

## 二、字段口径

| 本地模块 9 字段 | 取数口径 |
|---|---|
| 欧赔初赔 主/平/客 | 欧指「平均值」的「初」一行 |
| 欧赔即时 主/平/客 | 欧指「平均值」的「即」一行 |
| 亚盘初盘 | 亚盘各行「初始」让球值的众数；水位取澳门与皇冠 |
| 亚盘即时盘 | 同上「即时」列 |
| 亚盘初盘水位 上/下 | 澳门、皇冠初始的主/客水位 |
| 大小球初盘 | 大小球各行「初始」总进球线的众数 |
| 大小球即时盘 | 同上「即时」列 |
| 大小球水位 大/小 | 澳门、皇冠的大球/小球水位，**按第四节列序规则归位后**记录 |
| 采集时间 | 页面无发布时间 → 记抓取时点，并标「页面无时间戳」；同时必须落 `odds_<编号>.json` 供 §六 交叉校验 |

赔率一律十进制，水位保留两位小数。让球值换算：`平手 0`、`平/半 0.25`、`半球 0.5`、`半/一 0.75`、`一球 1.0`、`一/球半 1.25`、`球半 1.5`、`两球 2.0`；带「受」为负值（主队受让）。

大小球线 `3/3.5` 记 3.25，`2.5` 记 2.5，不要取整。

### 大小球三列的列序（易错点，必读）

懂球帝大小球行的三列顺序在不同场次不一致：有的页是「盘口｜大｜小」，有的页是「水位｜盘口｜水位」。直接按「盘口｜大｜小」硬解会把**大球与小球水位互换**（261117 周二006 就是这样把 3.5 大1.04/小0.76 读成 3 大0.76/小1.04）。

固定按数值特征判列序，不按位置猜：

```text
盘口：2.5 ≤ v ≤ 5.0      水位：0.60 ≤ v ≤ 1.20
中间数是盘口 → 顺序为「水位｜盘口｜水位」，大球 = 第三数，小球 = 第一数
首数是盘口   → 顺序为「盘口｜大｜小」，按序记
三数都不落在这两个区间 → 该行作废，重抓，不得硬解
```

自校命令（不依赖 008，随时可跑）：

```bash
python3 scripts/check_odds_vs_008.py --columns "0.76 3 1.04"
# → 列序＝水位｜盘口｜水位：盘口 3，大球 1.04，小球 0.76
```

## 二点五、结构化快照（交叉校验的输入）

盘口数字除了进 MD，必须同时落一份 `odds_<编号>.json`，schema 固定为 `odds-v1`。这是与 008 同时点比对、以及事后复盘的唯一机读凭据；只写在 MD 里无法自动拦截滞后值。

```json
{
  "schema": "odds-v1",
  "match_id": "周二006",
  "captured_at": "2026-11-17T19:25:00+08:00",
  "europe": {"initial": [2.27, 3.83, 2.73], "current": [2.52, 3.93, 2.45]},
  "asian": {
    "macau": {"initial": {"line": 0.0, "up": 0.84, "down": 1.00},
              "current": {"line": 0.0, "up": 0.94, "down": 0.90}},
    "crown": {"initial": {"line": 0.25, "up": 1.04, "down": 0.84},
              "current": {"line": 0.25, "up": 1.08, "down": 0.81}}
  },
  "total": {
    "macau": {"initial": {"line": 3.25, "over": 0.96, "under": 0.84},
              "current": {"line": 3.25, "over": 0.84, "under": 0.96}}
  }
}
```

- `line` 用数值（平手 0、受让为负、`3/3.5` 记 3.25），不用中文。
- `current` 必须是**本次抓取那一列**的原始值，不做任何主观修正；修正由校验脚本判定并记录。
- `captured_at` 用 ISO 8601 带时区，且必须 ≤ 竞彩开赛时间。

## 三、落库粒度

不必把 15–17 行全抄进 MD。模块 9 固定落三类：

1. **澳门** 初始 + 即时（水位 + 盘口）
2. **皇冠** 初始 + 即时
3. **全市场共识**：盘口众数 + 水位中位数 + 变盘家数（如「平手 → 平/半，11/15 家已变」）

需要 company 级明细时另存 JSON，MD 只留摘要。

## 四、变动与背离标记（只描述，不判断）

| 标记 | 触发条件 | 写法 |
|---|---|---|
| 升盘 / 降盘 | 共识让球值绝对值变大 / 变小 | 「平手 → 平/半，升 0.25」 |
| 水位位移 | 同一盘口下主/客水位变化 ≥ 0.10 | 「主水 0.91 → 1.05，变动 0.14」 |
| 欧亚背离 | 欧指方向与亚盘让球方向相反 | 「欧指主胜由 2.46 收至 2.28，亚盘同步升盘，同向」 |
| 盘口分裂 | 同一时点出现两种及以上盘口且各占 30% 以上 | 「即时盘平手 7 家 / 平/半 8 家，分裂」 |

竞彩-欧赔、竞彩-亚盘的背离判定统一见第七节，本节不再另设阈值，避免两套口径。

这些只作描述字段，禁止写「庄家看好」「诱盘」之类结论——判定属 Step2。

## 五、降级链

1. **懂球帝 `lotteryOddsNew`**（首选，初始+即时+多公司）
2. **新浪「竞彩欧亚对照」当日文章**（每日早间发布，给亚洲盘与换算盘口，单公司，可作交叉校验）
3. **竞彩官网总进球 SP**（`lottery.gov.cn/jc/jsq/zqzjq/`）——只记「总进球分布」，**不得冒充大小球盘**
4. 以上全失败：模块 9 对应字段标 `[未获取]`，并写明尝试过哪三个源

竞彩官网 SP（胜平负/让球）始终必采，属官方口径，与欧指、亚盘构成三方对照。

## 六、校验

### 6.1 结构自校（不依赖外部）

- 同一时点至少两家公司；只有一家时标 `[待确认]`。
- 初始与即时必须成对记录，缺一边不算采到。
- 大小球线、让球值必须换算成数值后复核一次，`3/3.5` 不可写成 `3`。
- 大小球三列先过 §二「列序规则」，`--columns` 自校不通过就重抓。
- 盘口时点与采集截点冲突（页面显示已开赛）时，整段作废并标「已开赛不可用」。

### 6.2 时点交叉校验（硬性拦截，无 008 则不得定稿）

**根因**：页面上没有时间戳，「即时」列不保证等于抓取时点。261117 周二006 采集于 19:25，页面给的却是 11:30 的值（澳门亚盘 0.84/平手/1.00、欧指 2.28/3.83/2.73），而 008 的 19:00 实为 0.94/0.90、2.52/3.93/2.45。这类滞后会直接推翻「竞彩与亚盘方向相反」之类的结论。

**规则**：抓完盘口、写 MD 之前，必须与当日 `008 赔率时间线` 同一场的**不晚于采集时点的最近时点**逐字段比对，阈值如下：

| 字段 | 阈值 | 命中判定 |
|---|---|---|
| 欧指均值（主/平/客任一） | 相对偏差 > 3% | `[STALE_EU]` 时点滞后 |
| 亚盘让球值 | 差 ≥ 0.25 格 | `[STALE_LINE]` 时点滞后 |
| 亚盘水位 | 差 ≥ 0.05 | `[STALE_WATER]` 时点滞后 |
| 大小球盘口 | 差 > 0 | `[STALE_TOTAL_LINE]` 时点滞后 |
| 大小球大/小水位 | 与 008 正好互换 | `[SWAP_TOTAL_WATER]` 顺序误读，按 008 归位 |

```bash
python3 scripts/check_odds_vs_008.py --odds odds_006.json --report 008_261117_终报.md
```

- 退出码 1 = FAIL：**该盘口段不得交付、不得用于欧亚背离与升降盘判定、不得写进 L7 的"即时"结论**；要么重抓，要么在 MD 里标 `[时点存疑]` 并把七时点里最接近的一个作为参照值（标明参照时点）。
- 008 尚未生成（采集早于首个时点）→ 输出 `无法交叉校验` 警告：盘口只作「初盘/参考值」记录，模块 9 的背离段整段写「未校验，不判定背离」。
- 008 的时点密度可能低于采集频率：参照时点取「不晚于 captured_at 的最近一个」，不要拿后一个时点反推。

## 七、三方对照与背离（固定输出项）

模块 9 末尾必须固定输出一段「三方对照」，不得省略；无背离时写「无背离」，不得留空。

### 三方定义

| 方 | 取数 | 角色 |
|---|---|---|
| 竞彩 SP | 官方胜平负 + 让球胜平负，含开售初值与当前值 | target |
| 欧指均值 | 懂球帝欧指「平均值」初始 / 即时 | reference |
| 亚盘共识 | 15 家让球值的众数，初始 / 即时 | reference |

### 背离判定（命中任一即标记）

| 类型 | 条件 |
|---|---|
| `SP-EU 动态` | 同一结果（主/客）的竞彩相对变动与欧指相对变动方向相反，且两者相对变动差 ≥ 3% |
| `SP-EU 静态` | 竞彩某结果与欧指均值同结果相差 ≥ 8%（不需变动，同一时点即可比） |
| `SP-AH` | 竞彩让球方向与亚盘共识让球方向相反（一方升盘、一方降盘），或让球值差 ≥ 0.5 格 |
| `EU-AH` | 欧指方向与亚盘共识方向相反（赔率收窄但盘口降，或反之） |

相对变动 =（即时 − 初始）/ 初始 × 100%，保留一位小数。

### 固定输出格式

```text
三方对照
竞彩 SP：主 2.40→2.38（-0.8%）｜平 3.50→3.78（+8.0%）｜客 2.29→2.20（-3.9%）
欧指均值：主 2.46→2.28（-7.3%）｜平 3.61→3.78（+4.7%）｜客 2.48→2.70（+8.9%）
亚盘共识：平手 → 平/半（升 0.25，8/15 家）
大小球共识：3 → 3.25（升 0.25，12/17 家）
背离：SP-EU 动态（客胜：竞彩 -3.9% vs 欧指 +8.9%，差 12.8%）、SP-AH（竞彩客胜收窄 vs 亚盘升盘）
```

只写数值与方向，不写「庄家看好」「诱盘」「资金真实意图」等判断；判定与取舍属 Step2。

### 与 Step2 的衔接

Step2 引用本段时必须同时给出一条反向解释（例如「竞彩客胜收窄可能来自散户集中，未必是机构方向」），只列背离而不给反向解读的，视为不完整。

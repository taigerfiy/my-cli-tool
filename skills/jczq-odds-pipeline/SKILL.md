## 快照字段口径（261119 新增，勿混用）

| 字段 | 含义 | 用法 |
|---|---|---|
| `eu` | 已采三家（wl/lb/bet365） | 机构级对比 |
| `eu_avg` | **三家均值**（不是共识），由本脚本计算 | 仅作三家中心 |
| `eu_cons` | **欧赔共识**：`odds.xml <europe avg>`，已与 okooo「99家平均」逐场比对，同口径 | 判断市场共识、算竞彩溢价 |
| `rq_cons` | 让球欧赔共识：`<rq avg>` | 让球SP 溢价比对 |
| `eu_spread` | 三家极差（n=3 只能算极差，算不了离散度） | 分歧粗筛 |
| `close_gap_h` | 竞彩截止 → 开赛 小时差（今日巴甲实测 8.5～10.5h） | 双锚分析：截止后海外盘仍在走 |
| `buyend_suspect` | 截售时间晚于开赛（页面脏数据） | 出现即该场不参与 gap 口径 |
| `fetched_at` | 真实采集时刻（非名义时点） | 计算真实采样间隔 |
| `xml_age_min` | 快照滞后分钟数 | ⚠ 上游 `updatetime` 约 60s 推进一次但内容常未变，**不能当价格新鲜度**；判新鲜度用内容哈希 |
| `xml_hash` | 场次内容哈希（`<matches>` 段 md5 前 12 位） | 时间线去重/丢弃乱序点：hash 未变=无新信息，hash 回退=命中旧节点缓存 |
| `seq` | **当日第 N 次采样**（261119 新增；补采点也入序，序号不跳空） | 引用某次采样的唯一短号 S01/S02…，报告里与场次号并列使用 |
| `prev_tp` / `prev_fetched_at` | 前一次快照的名义时点 / 真实采集时刻 | 算真实采样间隔；`fetched_at - prev_fetched_at` 才是本次的信息增量窗口 |
| `fields_changed` / `changed_vs_prev` | 与前一快照逐字段比对后的变更字段数 / 是否有变更 | 为 0 时报告必须写「本时点无新信息」，**不得**把本时点的值当成"本时点才变成的值" |
| `changes` | 逐字段变更明细 `[{no,key,from,to}]` | 时点汇总与台账交叉核对；单场异动只取这里，不另算 |

## 采样阶梯（261119 结论；19:30/20:30 已上线，其余待 P1）

- 单锚必错：竞彩截售 22:00 与开赛（次日 06:30～11:00）差 8.5～10.5h，两条线右端一个冻结一个还在走。
- 真实盲区（261119 更正）：**不是"21:00 后全空"**——21:55 完整版已有末段补采。真实空白是两块：
  1. 21:00→21:55 的 55 分钟内无中间点（由 21:55 完整版自身承接，不另建点）；
  2. 上午开售前的早期定价段（见下方"左端"）。
- **截止后不采（261119 用户口径，硬规则）**：22:00 成交截止后没有可下注窗口，海外盘继续走也不产生可交易信息；只能作复盘时"最终收盘"的归因参照，优先级最低，不进 P1。原"海外线 22:00 后继续采"的方案作废。
- 末段实测（11-16、11-18）：21:00→21:55 约 50～75% 场次有变动，幅度多在 0.05～0.25，偶发升降盘——有信息但很小，故不必加密到分钟级。
- **左端才是重点（P1 方向）**：海外开盘早于竞彩开售，但 `odds.xml` 只含"当日 + 次日预售"两套，左端硬上限 T-1 天；T-2 及更早取不到，想取只能另找源。
- 左端实证（261119 周四004）：11:30、13:00 该场 `in_sale=False`，但 SP 已有值并在变（主胜 1.80→1.76），15:00 才 `in_sale=True`。说明**竞彩 SP 在"可投注"之前就已发布并调整**，这段早期定价其实已经采到，只是没被当作独立口径使用。
- ~~待验证：加 09:30 固定采点~~ —— **261119 否决**。竞彩 SP 投放时刻每场不同（有的提前 24h 就挂、有的当天开售后才可见），固定钟点会让每场"相对发布时刻的进度"完全不等，采到的既不是初赔也不可比。已改用 11:10 预触发 + 初赔 hook 的思路（见下条）。
- 左端正确做法：**以每场自身的事件为锚**，不用统一钟点。三个锚点：
  1. `SP 发布时刻`（真初赔时点）——只能从源页时间列取，或退化为"首次观测到非空"的上界；
  2. `首次 in_sale=True`（可投注时点）——由时间线派生，261119 实测 004 比 SP 发布晚 3.5h；
  3. 临场各时点。
- 初赔 hook 现状（`/home/user/Doubao/jczq_shared/scripts/init_odds.py`）：已能取到竞彩官方初值(cid=1)、wl/lb/bet365 初赔、am/hg/bet365 初盘，并新增时间戳字段。
- 时间戳可得性（261119 实测）：
  - **亚指页有**「初始盘口 + 变化时间」两列，逐公司可取（实测出现 11-08 05:05，即 T-11 天）；这是目前唯一能拿到"海外真实开盘时刻"的地方。
  - **欧指页没有**初盘时间，只有行上的 `data-time`（即时更新时间）；欧赔只能用"首次观测"作上界。
- **左端时间戳口径（261119 已落地）**：`init_asian_time` = 亚指「初始盘口」右侧时间列，是目前唯一能拿到的海外真实开盘时刻；`open_ahead_h` = 最早一家开盘距开赛的小时数。欧指页无此列，欧赔起始时点只能用"首次观测"当上界（`tp_anchors.py` 的 `first_sp_tp`）。
  - ⚠ 噪声：实测同批场次的 am/hg 开盘时刻会集中到同一分钟（如三场都是 11-16 22:06），属数据商批量落库而非各机构真实开盘；单场可用，横向比"谁先开盘"要剔除这种 batch 值。
  - 实测分布（261119）：bet365 最早 T-19 天（11-02 03:37）、hg T-16、am T-2～T-3，说明海外开盘本身离散，不能用一个钟点覆盖。
- **`in_sale` 与 SP 是两件事（261119 实证）**：周四004 在 11:30/13:00 `in_sale=False` 但 SP 已有值并在变（1.80→1.69），15:00 才可投注。→ 判"是否已发布"看 SP 非空，判"能否下注"看 `in_sale`，不得混用。
- 次日编号场次当天就可能已有官方初值（实测 261119 的 周五001-008 已在 trade 页带 `data-buyendtime` 与初值），也有仍为 None 的（周五006 拜仁）——正是"投放时间不固定"的直接证据。
- T-3～T-7 的海外早盘：`odds.xml` 只含当日+次日，取不到；建议只用 init 初盘 + 亚指初盘时间做单点锚，不上时间线。
- 阶梯步长下限 = `xml_refresh_probe.py` 测出的**内容变更间隔**，不是 updatetime。261119 实测安静时段约 2～6 分钟一变盘（15 次/小时）。
- 已知上游缺陷：多节点缓存不一致，会出现 `updatetime` 倒退，时间线需按内容哈希去重排序。

```bash
S=/home/user/.doubao/agent_mode/workspace/.user_skills/jczq-odds-pipeline/scripts
D=/home/user/Doubao/jczq_shared/work_<YYMMDD>

# 1) 采样（同一时点快照：欧赔/亚盘/五玩法SP/必发）

python3 $S/convert_legacy_tp.py <YYYYMMDD>

# 5) 刷新粒度探测（定阶梯步长前必跑一次；按内容哈希算，不看 updatetime）
python3 $S/xml_refresh_probe.py --minutes 20 --interval 20 --out $D/probe_<YYMMDD>.json

# 6) 事件锚点派生（SP 首现 / 首次可投注 / 时段位移；任意时点有新快照后可重跑）
python3 $S/tp_anchors.py --dir $D --out $D/anchors.json

# 7) 初赔+初盘（含亚指真实开盘时刻）——init_collect 的产物里有 init_asian_time / open_ahead_h

# 8) 事件探测（投放时刻不固定：命中 SP 首现/首次可投注才补采一条完整快照）
python3 $S/collect_tp.py --date <YYYY-MM-DD> --prefix 周X --tp <HHmm> --probe --dir $D

# 9) 临场分钟级盯盘（**已实现但不上线**：261119 用户定为"最后两小时每半小时一次"，
#    本脚本仅在单场专项排查时手工调用，勿建定时任务）
python3 $S/tp_minute_watch.py --date <YYYY-MM-DD> --prefix 周X --start-tp 2100 \
  --minutes 5 --interval 60 --sp-every 5 --dir $D

# 10) 字段级台账（出「每个值自哪次采样起未变」；写时点报告/终报前必跑一次）
python3 $S/tp_ledger.py --dir $D [--day <YYYYMMDD>] [--match 周XNNN]
```

临场分钟级要点：
- `odds.xml` 仅约 9KB / 12 场，含 3 家欧赔 + 99 家共识 + 让球共识 + 4 家亚盘 + 2 家大小球（每场约 33 个数值字段），所以分钟级抓取的带宽成本可忽略。
- 上游内容实测约 15 次/小时变更（平均 4 分钟一变）→ **1 分钟采样即完整覆盖，不会漏变化**，同时也意味着 60 个点里大部分是重复，故只写"变化行"（`minute_<YYYYMMDD>_<HHMM>.jsonl`），不写全量点。
- 每 5 分钟抓一次 SP 页（`--sp-every 5`）：竞彩官方 SP 调整稀疏，1 分钟抓是浪费。
- 窗口只在**截止前**（可下注区间内）；截止后不采（硬规则见"采样阶梯"）。

探测模式要点：
- 只抓一个玩法页判事件；命中 `sp_first`（SP 首次非空）或 `sale_first`（首次 `in_sale=True`）才强制重抓并写 `all_<YYYYMMDD>_<HHmm>.json`，快照带 `trigger: probe` 与 `events`。
- 状态落 `probe_state_<YYYYMMDD>.json`（每场 `first_sp_at` / `first_sale_at` / `sp_now`），重跑不重复触发。
- 无事件不写快照，只更新状态——故可高频轮询而不污染时间线。

## 硬规则

1. 场次映射：odds.xml 同时含当日（processname `3xxx`）与次日预售（`4xxx`），按 **processname 首位星期键 + 编号三位** 匹配，禁止后三位切片（否则串场）。
2. 只采「竞彩编号当天前缀」场次；次日凌晨场仍算当天在售。
3. 会话输出压缩：非落库时点 ≤5 行、落库时点 ≤5 行、21:00 终报 ≤1 行＋链接；明细只进 008 与 json。
4. 单文档 ≤20 页（A4 估算：表格行 22pt／正文行 26pt／可排 700pt），超页按场次拆卷《…报告_卷N》。
5. 标题六位日期前缀：`YYMMDD赔率时间线_HHmm`、`YYMMDD赔率时间线报告`；本地文件仍用八位。
6. 终报覆盖当日全部编号场次（含已停售），场次数与编号总数逐场核对。
7. 必发未收录写「必发页未收录，无必发数据」，不得编造。
8. 时点报告/终报/JSON 只存 008，不同步 016；全部时间为北京时间。
9. 交接卡：每轮必读 011/04《豆包261116_竞彩会话交接卡.md》（`drive +download` 的 file-token 见本地部署版，公开仓库不写真实值），抬头照抄 11.1 三段指纹。
10. **时点归因口径（261119 新增，硬规则）**：任何时点/终报里写价格，必须带"自哪次采样起未变"，格式「主胜 1.48 自 S06 起未变，此前 S05 为 1.55」；禁止写成「15:00 主胜 1.48」这种把区间漂移压成瞬间跳变的表述。`fields_changed=0` 的时点，结论一律标「本时点无新信息」，不得拿它当变盘证据。
11. 上游无机构级时间戳（`odds.xml` 只有一个全局 `updatetime`），真实变价时刻不可得；只能给"首次观测"上界。结论里不得声称精确到分钟的真实变价时间，需要精度就加密采样。
